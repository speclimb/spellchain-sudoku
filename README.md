# 連鎖詠唱ナンプレ

数字の起点を選び、連鎖で戦う日本語ブラウザゲーム。Phaser / TypeScript / Vite。PCとスマホ縦画面に対応しています。

**[ブラウザで遊ぶ](https://speclimb.github.io/spellchain-sudoku/)**

リポジトリ: [speclimb/spellchain-sudoku](https://github.com/speclimb/spellchain-sudoku)

## 起動

Node.js 24以降を使用します。

```sh
npm install
npm run dev
```

ブラウザで http://127.0.0.1:5173 を開きます。配布用ファイルは `npm run build` で `dist/` に生成され、通常の静的ホスティングに配置できます。サーバー処理やアカウント、外部の画像・フォント配信は不要です。

スマホ実機で開く場合は同じLAN上で `npm run dev -- --host 0.0.0.0` を実行し、PCのLANアドレスの5173番ポートへアクセスします。開発サーバーをインターネットへ公開しないでください。

## 遊び方

タイトルの「遊び方」ボタンで、基本操作を短く確認できます。「詳しいルール」は従来のヘルプにつながります。閉じる・背景タップ・Escでタイトルに戻り、冒険や保存データは変わりません。

1. 術師を選んで冒険開始。青緑の枠の数字は、候補が1つで正解が確定しています。
2. マスを選ぶと連鎖経路、ダメージ、被ダメージが表示されます。起点は何度でも選び直せます。選択中は●、他の選べる起点は○と細い枠で示し、連鎖経路の中でも見分けられます。★は冒険の最初から表示され、現在の通常／スキルで最長になる全起点です。
   「連鎖のしくみ」を開くと、前へ・次へで1マスずつ確認できます。水色の枠が直前のマス、金の枠が次のマス、明るい帯がつながる行・列・区画です。予告の確認で手数や魔力は消費しません。
3. 「詠唱する」で確定。Lv.1では起点＋自動3マス、導火術師はさらに＋1マス。術式レベルが1上がるごとに自動入力も1回ずつ増えます。
4. 行・列・3×3区画の完成は、短い全画面の魔法カットインと追加ダメージ。✧は弱点、◇は守護＋6。同じシートで獲得した守護は蓄積し、完成時を含む毎回の反撃を軽減します。残り数マスを埋める手でも守護が消えません。
5. 魔力8または五の護符の無料券があると、スキルで未確定マスからも始動できます。通常詠唱は入力1マスにつき魔力＋1、1詠唱のマス由来分は最大5。蓄光術師の＋1と蓄電石は別加算です。固有スキル＋装備した追加スキル2枠から、1詠唱に1つだけ選びます。魔力と無料券は共通で、無料券を先に使い、魔力と蓄電を温存します。スキルの手では充電されません。
6. 上位・長い導火線があれば、シート完成時の残り自動入力回数で次のシートへ連鎖します。攻撃と反撃は全シートの詠唱後に各1回。その詠唱中の最大シート守護値を使い、足し合わせません。未所持なら従来どおり完成・反撃後に新シートへ移ります。
7. シート完成と敵撃破で術式レベル＋1。レベルごとに自動入力＋1回、攻撃倍率＋0.2、最大HP＋4、HPを最大10回復。通常の敵撃破では遺物などの3択から1つ選びます。5・10・15戦目以降も5戦ごとにボスが登場し、スキル3択から1つ、続いて遺物3択から1つの両方を受け取れます。連戦は終わらず、後半は敵の攻撃が成長を上回ります。HPが尽きた時点でスコアと撃破数を記録します。敵撃破による残りマスの一掃はシート完成の成長に含みません。

PCでは矢印キーで盤面のフォーカスを移動し、Enterで起点を選択できます。入力の確定は別の詠唱ボタンで行います。考えている間は敵が動かず、時間制限や時間による得点差はありません。

連鎖は毎回「直前に埋めたマス」と同じ行・列・3×3区画にある確定マスから、縦の距離＋横の距離が最短のものへ進みます。同距離なら上の行、次に左の列を優先。最初から確定していたマスも対象です。自動入力回数が0になるか、次につながる確定マスがなくなると終了し、その理由も予告に表示します。導火術師は術式Lv.1で通常最大5連鎖、固有スキルLv.1で最大9連鎖。術式Lv.10・固有スキルLv.1なら14／18連鎖になり、スキル強化や遺物でさらに増えます。上位・長い導火線があれば36連鎖を越えて続きます。連鎖数そのものに36／72などの上限はなく、残り自動入力回数か接続先がなくなると終了します。

## スキル・遺物の成長とボス報酬

**術式レベル、スキルレベル、遺物レベルは別の成長です。** シート完成・撃破による術式レベルの成長は継続し、スキルと遺物はそれぞれLv.1〜10まで強化できます。報酬カードには現在→次の効果を表示します。

- **スキル装備**：術師固有の1つは常に使用可能で、追加2枠を使いません。追加スキルは3種類をすべて習得でき、報酬画面で2つまで装備します。外しても所持とレベルは残ります。戦闘中の付け替えはできません。空き枠がある間は新規習得時に自動装備します。
- **スキル成長**：Lv.5・10が進化の節目です。導火術師の星火連環は自動入力と同じ数字への飛び火、紋章術師の大紋章の詠唱は完成倍率、蓄光術師の月光解放は通常攻撃倍率を強化します。初期Lv.1・2の固有効果は以前のランク1・2と同じです。他の術師の固有スキルは習得しません。
- **連星渡り**：接続が途切れると、残り自動入力1回を使って最も近い確定マスへ再接続。回数はLv.1／5／10で1／2／3回、自動入力は＋0／3／8。同距離なら上→左です。
- **貫星弾**：実際に埋めた弱点1マスごとに追加攻撃。Lv.1／5／10で24／40／55×術式倍率。Lv.5から弱点3マス以上で60、Lv.10では100×術式倍率をさらに1回加算します。
- **護星砲**：詠唱中の最大シート守護×1.5／2.5／3.6×術式倍率を追加攻撃（Lv.1／5／10）。Lv.5では一時守護＋6、Lv.10では＋14。一時守護はその詠唱の攻撃と反撃に使い、シートには残しません。複数シートの守護は合算しません。

貫星弾・護星砲の追加攻撃は整数化して加算し、一筆・硝子・魔力増幅器・月光解放・三の護符の倍率やシート完成加算を重ねません。どのスキルも共通の魔力8または無料券1枚で使い、固有スキルと追加スキルの効果を同時に発動しません。術師の常時効果は維持します。

**遺物16種・所持8枠**。満杯のときに新しい遺物を選ぶと、手放す遺物と効果を比較して入れ替えます。所持品の強化・進化は枠を使いません。手放したレベル・進化段階・護符の取得回数は記録され、再び報酬で選ぶと復元されます（復元時のレベル加算はなし）。蓄電・無料券・自動入力予約は対応する遺物を手放すと消えます。以前の保存で8個を超えている遺物は削除せず、新規取得は交換になります。

所持中の遺物は同じ遺物の報酬でLv.10まで成長。通常・上位・極位の3段階はレベルと独立し、ボス報酬で1段階ずつ進化します。極位には上位かつLv.5以上が必要です。段階は旧効果を置き換え、旧倍率をさらに重ねません。硝子の杖は所持中だけ最大HP−8。手放すと上限が戻りますがHPは回復せず、再取得時には再び−8になります。強化時は再減少しません。

- 報酬は遺物3択が基本です。候補が残る限り「新規取得」と「所持品の強化」を各1枠保証します。遺物候補が3種以上ある場合、25％の確率で残り1枠が「術式の鍛錬」「生命の器」「癒しの泉」になります（ボスでは祝福も候補）。術師の適性による優先抽選はせず、通常戦では新規と強化を可能な限り異なる系統から選びます。片方の候補がない場合は別の遺物で補います。
- ボスで進化条件を満たす遺物は、通常成長との候補選びで進化の重みがLv.1〜2／3〜4／5〜7／8〜9で2／3／4／5倍。Lv.10では通常成長が候補から外れます。さらにボスの所持枠・残り枠で進化候補を優遇します。これは3択全体への出現率とは異なり、所持状況・他の候補・導火線保証で変わります。進化は引き続きボス限定です。
- 第3戦以降、長い導火線が未所持なら新規取得の枠に必ず登場します。所持していて上位未取得なら、ボスの遺物3択の強化枠に上位・長い導火線を必ず提示し、選ぶまで継続します。取得は任意で、抽選済みの保存中の3択は変更しません。
- ボスは「1/2 スキル」→「2/2 遺物」の2段階。スキル側も、可能なら未習得と所持スキルの成長を各1枠保証します。各段階で選ぶのは1つです。同じ遺物の通常版と進化版が同じ3択の2枠を占めることはありません。
- 両段階の候補は撃破時に抽選・保存し、再読み込みや装備変更で再抽選しません。1段階目の選択では次の敵へ進まず、2段階目の選択後に進みます。
- 候補不足は「術式の鍛錬」「生命の器」「癒しの泉」で補います。スキル全最大でも3択は継続。ボスの遺物成長候補がすべて尽きると、鍛錬・魔力の祝福・守護の祝福の3択になります。以前の「上位7種を集めたら終了」ではありません。
- 魔力の祝福は次の5戦の開幕魔力8、守護の祝福は次の5戦の反撃25％軽減。同種は重ならず残り5戦へ更新し、ボスの2段階選択で2戦分減ることはありません。

### 遺物の重要なルール

- **一筆の杖**：最初の数マスが生んだ基本・完成・弱点ダメージを増幅。長い連鎖でも効果は残ります。Lv.1の通常／上位／極位は最初の3／5／7マスに2倍、さらにレベルで対象数と倍率が増加します。
- **蓄電石**：通常詠唱に追加充電し、超過分を別に蓄え、有料スキル直後に魔力へ戻します。Lv.1通常では充電＋1・蓄電上限2、Lv.10極位でも充電＋10・蓄電上限4。無料券使用時は魔力・蓄電を保ち、スキル自身では充電しません。蓄えは戦闘を越えて保持します。
- **共鳴石・再燃の輪・残光の灯**：共鳴は起点と同じ数字への無料入力で、Lv.1／5／10に最大1／2／3マス。再燃は詠唱全体の最初の行・列・区画完成で1回だけ自動入力を補充。残光は次の通常詠唱への予約で、スキルを続けても予約を加算しません。
- **素数の護符**：二・三・五・七は対応する数字を実際に埋めた詠唱につき、効果ごとに独立して1回だけ抽選。シートを越えて同じ数字を何度埋めても抽選は増えません。最初の3取得は正確に30／45／60％。取得ランクと上位段階は独立して保存し、Lv.4以降はレベルによる確率成長が加わります。発動率上限は80％です。
  - 二：守護を引いた後の反撃を軽減。Lv.1〜3の通常25％・上位50％を維持し、極位は60％。祝福との合計上限も60％で、軽減後は端数切り上げ。
  - 三：通常攻撃部分を増幅。Lv.1〜3の通常1.5倍・上位2倍を維持し、極位の基礎値は2.4倍。シート完成加算と追加攻撃は増幅しません。
  - 五：次のスキルを無料にする券を通常1／上位2／極位3枚（保有上限も同じ）。券所持中・無料スキル中は抽選しません。
  - 七：次の詠唱の自動入力を予約。Lv.1〜3の通常＋7・上位＋14を維持し、極位の基礎値は＋21。Lv.4以降は回数も成長。予約は1件で加算せず、現在の経路には影響しません。
- **最長起点の標準表示**：遺物の有無に関係なく、現在選んだ通常／スキルで、シート越えを含む最長連鎖になる全起点に★。「最長N連鎖・候補Mか所」も表示します。最長連鎖と最大ダメージは同じとは限りません。
- **弱点のレンズ**：通常の弱点追加ダメージは16＋（Lv−1）×2、上位・極位で各＋4。弱点を起点に選ぶと、その1マスだけさらに8＋floor((Lv−1)/2)＋(段階−1)×4。長い連鎖に混ぜるだけでなく、起点選びで効果を高められます。
- **上位・長い導火線**：完成時の残り自動入力を新シートへ持ち越し、そのシート内で最長につながる確定起点へ入ります。同長なら上→左。新シートの最初の入力も自動1回を使い、行・列・区画による接続を維持します。
- **黄金のインク**：攻撃由来スコアを増幅し、通常詠唱で行・列・区画を完成すると反撃前にHP回復。Lv.1通常で2、Lv.10極位で7。1詠唱に1回で、複数の完成やシートを越えても加算されません。敵撃破の固定500点は別加算です。
- **倍率と成長**：硝子の杖と魔力増幅器の攻撃加算率を合算します（Lv.1ならスキル時＋20％＋35％＝＋55％）。術式・固有スキル・三の護符は各ルールを維持。導火線・再燃・守護のレベル成長を緩やかにし、Lv.10極位ではそれぞれ自動＋11、再燃＋13、完成1単位の守護＋13です。

この遺物調整は `origin/main` の `6c10611` を基にしています。旧保存は現在の戦闘・抽選済み報酬を保ち、最後の報酬を選んで次の戦闘へ進むと新数値へ移行します。比較は `node scripts/relic-balance-report.mjs`、短い確認は同コマンドに `--quick`。結果は `.runtime/relic-balance/report.json` に出力されます。数式・互換性・検証範囲は [RELIC_BALANCE_VERIFICATION.md](RELIC_BALANCE_VERIFICATION.md) を参照してください。

数値の完全な定義は [`src/game/growth.ts`](src/game/growth.ts)、実装範囲と検証状況は [`GROWTH_VERIFICATION.md`](GROWTH_VERIFICATION.md) に記載しています。

## 一詠全成・予告・戦闘の処理

シート完成の追加ダメージは、シートごとの通常攻撃をD、この手で実際に埋めたマス数をN、初期空きマス数をBとして `floor(D × 0.25 × N / B)` を計算し、合計します。全詠唱の攻撃を各シートに重複計上しません。現在の全問題は初期数字45・空き36なのでB=36。最後の1マスだけなら1/36分、手付かずの36マスを1回で埋めた「一詠全成」なら最大25％を加算します。敵撃破後の見た目の一掃は含みません。一詠全成の光・音・内訳は短縮・動きを抑える・消音設定に対応します。

処理順序は「各マスの基本・完成・弱点（一筆を適用）→術式・選択スキル・通常倍率→シート別に整数化したD→三の護符による通常攻撃増幅→シート完成加算とスキル追加攻撃→敵の装甲→攻撃スコア→撃破判定→黄金のインクの回復→未撃破なら反撃→生存時の成長・回復」です。自動入力と術式倍率は詠唱開始時に固定。共鳴・再燃・飛び火・再接続の回数は詠唱全体で共有し、シート越えでリセットしません。成長は終了時に完成枚数＋撃破1レベルをまとめて反映し、その場の自動入力を補充しません。

1マスの基本ダメージは10、12……80で止めますが、連鎖数には36／72などの上限はありません。敵HPを超えても詠唱を完走し、超過分もスコアになります。次の敵へ攻撃せず、ボス報酬も飛ばしません。反撃には詠唱中の最大シート守護を使い、シート間で合算しません。

予告は護符を抽選せず、確定ダメージと発動確率・発動時ダメージを表示します。発動次第で撃破できる場合は反撃・回復・成長も幅を示し、不発なら敗北する手を安全とは表示しません。シート越えの予告は複製した問題乱数を使い、本番状態を消費しません。最長起点の検索は盤面・資源・選択スキルごとにキャッシュ。護符の抽選は冒険のシード・通算詠唱回数・効果ごとの固定領域で決まり、予告の回数や順序、再読み込みで変わらず、問題・報酬の乱数列から独立しています。

## 敵と次の行動

敵は8種類。開幕4戦の姿と5戦ごとのボスを保ち、通常戦には「霜牙の狼」「鏡甲の甲虫」も登場します。固有の姿・攻撃名・攻撃演出と、現在／次の反撃予告があります。

- 番人とボス：毎手反撃、3手ごとに攻撃力2倍。
- 霜牙の狼：溜め（攻撃0）と2倍の突進を交互に行います。
- 鏡甲の甲虫：最終攻撃の20％を切り捨てで軽減。行・列・区画のどれか1つを完成させると、その詠唱中だけ装甲が解除されます。
- その他：毎手、表示された攻撃力で反撃します。敵を倒した詠唱には反撃しません。

HPは最初の4戦が1400／2200／3200／4600、5戦目が6500。6戦目以降の基準HPはd=戦数−5として `6500＋1300d＋150d²＋100 max(0,d−10)²`。第15戦までは基準HPのまま、第16戦以降はe=戦数−15として通常敵は `基準HP × (1＋0.012e)`、5戦ごとのボスは `基準HP × (1＋0.04e＋0.0015e²)` を四捨五入します。いずれも安全な整数の最大値が上限です。進んだ戦数だけで決まり、遺物取得・術式レベル・プレイヤー火力では変動しません。

基本攻撃力は従来どおり `5＋floor(d/2)＋floor(max(0,d−5)²/8)`。撃破時の反撃0、シート越え、自動入力・味方倍率、強いビルドによるボス一撃も維持します。旧保存の戦闘中HPは据え置き、最後の報酬を選んで次の敵へ進む時に新HPへ切り替わります。調整の対比較と制約は [`CROSS_SHEET_BALANCE_VERIFICATION.md`](CROSS_SHEET_BALANCE_VERIFICATION.md) を参照してください。

## 育てた力の記録

ボス報酬画面の「育てた力の、働き。」で、現在のボス戦を含む直近5戦と、そのボス戦だけを切り替えます。最初に主な働きを最大3件、詳細には全スキル・遺物の実績と次の成長を表示します。

- 総ダメージを敵HPに与えた分と超過分に分離し、スコアは別集計。スキルの使用回数・平均ダメージは、そのスキルを選んだ詠唱全体の実績です。スキル単体の増分ではありません。
- 遺物の発揮ダメージ差は、同じ経路でその効果だけを外した差（超過分を含む）。効果同士が重なるため足し合わせず、100％の配分や強さランキングとして扱いません。防いだHPダメージも単一効果を外した差なので合計しません。
- 自動入力は付与順（FIFO）で使用元を記録し、付与と使用を別々に表示します。経路全体を回数増加遺物の成果とは数えません。共鳴の無料直接入力は自動入力の燃料と区別します。残光の予約更新は新規付与を水増ししません。
- 魔力、無料券の獲得／使用、軽減、追加スコアは別の単位です。所持中の詠唱数・発動機会・発動回数・少数サンプルを示し、未使用や機会なしを弱さの証拠にはしません。
- 記録は詠唱確定時だけ更新。予告・演出・保存再読込では加算しません。旧保存には過去の数値を捏造せず、再開後から計測した部分記録であることを表示します。

## 効果音と公開用素材

外部SEはCC0素材のみを採用しています。KenneyのInterface Sounds・Impact Soundsと、JaggedStoneのMagic Spell SFXから12音を同梱し、操作・詠唱開始・完成魔法・打撃・防御・シート完成・成長で使い分けます。連鎖の上昇音は合成音を重ねます。音素材は合計約76KBで、音がオンの状態で最初に操作したときに読み込みます。消音は演出中でも即座に反映し、読み込みに失敗した場合は合成音で続行します。

[出典・加工内容・ライセンス](THIRD_PARTY_NOTICES.md)と素材ごとのURL・ハッシュを保存しています。配布用にも`audio-licenses/`へクレジットとCC0原文を含め、設定画面から参照できます。

Phaserなど配布するライブラリの著作権・ライセンス通知は [`software-licenses/`](public/software-licenses/CREDITS.txt) にまとめ、公開サイトにも同梱しています。

ビルドは相対URLを使用するため、GitHub Pagesのリポジトリ配下にも配置できます。音源を含めて`dist/`一式を配信してください。実行時に素材サイトへの接続は不要です。

## 実装済みの内容

- シングルだけで解ける、一意解の9×9問題30問。毎回数字・行列・転置を変換し、30問を使い切るまで元問題を重複させず、以降は新しい順序で継続。境目でも同じ問題が続きません。
- 終わりのない連戦、累計敵撃破で解放する3キャラ、最初から全種類が報酬候補になる16遺物。固有＋追加2枠のスキル、各Lv.10までの成長、遺物3段階。5戦ごとのボスと2段階報酬。8種類の敵が再登場し、後半ほどHPと攻撃力が増加。最高撃破数とベストスコアを記録。
- 複数シートにまたがる戦闘と術式レベルによる成長。現在のシート数、自動入力の成長分、攻撃倍率、成長の予告を表示。
- 連鎖が伸びるほど強まる光の軌跡・火花・音、攻撃とスコアのポップアップ、被弾の赤い画面効果、完全防御の青い盾。行・列は光線、区画は魔法陣、同時完成は複合の全画面カットイン。多数の完成はまとめて表示し、長い連鎖でも演出時間が伸び続けない構成。短縮・動きを抑える設定に対応。
- 予告と実行で共通の決定的な連鎖処理。最短距離、同距離なら上・左に連鎖。確率効果は詠唱の確定時だけ解決し、予告では確定分と発動時の上限を分けて表示。
- 一手内の完成・弱点・共鳴・再燃・倍率・充電の処理。守護はシート内で蓄積して毎回の反撃に適用し、シート切替でリセット。「守護の紋章」の完成1単位につき加わる守護（Lv.1通常で＋3）も同様。完成時も反撃は残るため、敵の攻撃力が蓄積守護を超えればダメージを受けます。
- 超過ダメージを含む得点。一掃による追加得点・充電・効果発動はありません。
- 自動保存、中断・再開、ベスト記録、図鑑、初回ガイド、消音・短縮・動きを抑える設定。
- シート完成と敵撃破時の成長・HP回復、各巡のボスと番人の3手ごとの強攻撃。盤面完成時の反撃でHPが0になった場合は敗北します。

保存はこのブラウザのlocalStorage内だけです。端末間同期はありません。行動を解決してから描画するため、連鎖中にページを再読み込みしても同じ手や報酬を再処理しません。サイトデータ削除で記録は消えます。遺物は初回の冒険から全16種が抽選候補です。進行中の冒険も読み込み時に候補を追加しますが、抽選済みの報酬（ボスの次段階分も含む）は変更しません。以前の保存データは盤面・敵HP・魔力・報酬を保持して新しい形式へ移行します。旧保存の現在の敵は旧バランスのHPと反撃をそのまま使い、報酬を選んで次の敵へ進む時に新バランスへ切り替わります。旧保存の抽選済み報酬と問題・報酬の乱数状態は再抽選しません。抽選済みの旧ボス3択は従来の1段階のまま受け取り、新ボス報酬へ作り直しません。旧固有ランク・護符の取得ランクと上位段階は効果を保って移行し、過去の貢献記録は推定しません。

## 検証

```sh
npm test
npm run build
npm run test:browser
```

ブラウザテストはWindowsではMicrosoft Edge、それ以外ではPlaywrightのChromiumを非表示で使用します。Windows以外では先に `npx playwright install --with-deps chromium` を実行してください。ローカル開発サーバーを自動起動し、PCとスマホ相当の表示幅、通常入力とスキル、7戦目以降への継続と敗北、連鎖・攻撃・防御の演出、シート終盤の守護維持、シート切替時の守護リセット、保存・再開を確認します。音源12点の読み込み・デコード・再生開始、演出中の消音、音源欠損時の続行も検証します。スクリーンショットは `.runtime/screenshots/` に保存されます。

ビルド後に `node scripts/smoke-audio-pages.mjs` を実行すると、専用の一時サーバーで `/spellchain-sudoku/` 配下の配信を確認できます。JavaScript・CSS・音源・ライセンスの読み込みと実際の1手を検証し、終了時にそのサーバーを閉じます。

`npm run generate:puzzles` で収録問題を同じ固定シードから再生成・検証できます。

今回の成長拡張の検証範囲・実測値・制限は [`GROWTH_VERIFICATION.md`](GROWTH_VERIFICATION.md) を参照してください。以前の成長調整の測定は [`ENDGAME_VERIFICATION.md`](ENDGAME_VERIFICATION.md) に履歴として残し、新スキル・新報酬・新しい敵のバランス確認には流用しません。

`node scripts/growth-balance.mjs 2` は3キャラ×追加スキル3種×各2シードの18ランを初期状態から自動攻略します。キャラ・遺物を全解放したプールで、実際に抽選された報酬を選び、指定スキルを優先して育てます。スキルを初めから付与する検証ではありません。確定予告を比較する方針で隠れた護符の結果は参照しません。実測は `.runtime/growth-balance.json` に保存されます。これは人間のプレイ時間・楽しさ・最適戦略の保証ではなく、各ランの終了理由と記録の整合性を調べるための検証です。

回帰テストは、Lv.1〜10と進化、報酬の新規／強化保証、ボス両段階の中断・再開、装備制約、予告と実行の一致、無料券優先、新敵の行動・装甲、直近5戦の貢献記録、旧保存移行を含みます。ブラウザではPC・スマホの装備／スキル選択、貢献詳細、8種の敵演出、短縮・動きを抑える設定も確認します。

## GitHub Pagesへの公開

`main` へのpushで [GitHub Actions](https://github.com/speclimb/spellchain-sudoku/actions) がルールテスト、ビルド、ブラウザテスト、リポジトリ配下での音源・ライセンス配信確認を実行し、成功した `dist/` をGitHub Pagesに公開します。Pull Requestでは同じ検証だけを実行します。

公開元はリポジトリの Settings → Pages → Build and deployment → Source で **GitHub Actions** を指定します。手動で再公開するときは Actions の **Test and deploy GitHub Pages** から **Run workflow** を実行できます。

## 構成

- `src/game/`: 描画に依存しない盤面、戦闘、報酬、進行、保存の処理。
- `src/ui/`: Phaserの盤面と演出、操作用のHTMLグリッド、連鎖音。
- `src/main.ts` / `src/style.css`: タイトル、戦闘HUD、報酬、結果、図鑑、設定とレスポンシブ表示。
- `tests/`: ルール検証とブラウザ操作テスト。

公開インターフェースは `startRun(save, character, seed)`、`previewAction(run, cell, skill, skillId?)`、`resolveAction(run, action)`、`dispatch(save, action)`。追加スキルは行動の`skillId`で指定し、装備変更は報酬中の`equip`行動で行います。状態はシリアライズ可能で、処理は元の状態を変更しません。行動にはrevisionが必要で、古い行動の再適用は拒否します。

固定のクリア戦数や10分の制限はありません。後半は成長した長い連鎖で大量のマスを埋め、さらに速く強くなる敵にどこまで挑めるかを競います。自動攻略では成長・連戦の継続・実際の反撃による敗北を確認し、到達戦数や各戦の手数を記録します。難易度と爽快感の最終調整は人によるプレイでも確認します。

## 長い詠唱と保存

詠唱の記録はシート別の開始盤面と経路区間で構成し、マスを「通算シート＋座標」で識別します。新しいシートの同じ座標も別の入力です。全結果を演出前に保存し、途中の再読み込み・演出スキップ・動きを抑える設定でも入力・成長・報酬を二重に処理しません。一詠全成はそのシートの初期空き36マスを今回だけで埋めた場合に限り、途中まで埋まったシートの仕上げや敵撃破時の一掃とは区別して祝います。旧セーブのHP・抽選済み3択・問題／報酬乱数は維持し、新しい護符は未抽選の報酬から参加します。

今回の最長表示・レンズ・報酬調整の検証は [`RELIC_GUIDANCE_VERIFICATION.md`](RELIC_GUIDANCE_VERIFICATION.md) と [`RELIC_REWARD_VERIFICATION.md`](RELIC_REWARD_VERIFICATION.md) を参照してください。

## プレイ履歴

メニューの「プレイ履歴」から、進行中・敗北後・新しい冒険を始めた後も戦いを振り返れます。報酬画面と貢献レポートにも入口があります。

- 冒険を選び、戦闘一覧から各詠唱を開くと、使用スキルと当時のLv、連鎖数、通過シート、敵HPに与えた分と超過ダメージ、反撃と実際に失ったHP、遺物の発動・不発・具体的な効果を確認できます。
- 遺物の発動と無料券の発行・消費、自動入力の予約・実使用は別々に記録します。遺物のダメージ差・防御差は既存の貢献レポートと同じ「同経路でその効果だけを外した差」であり、相乗効果が重なるため合算できません。
- ボスの2段階を含む、実際に選択した報酬も記録します。予告・演出・スキップ・再読込は記録を追加しません。複数シートへ続く詠唱は1件です。
- 保存はこのブラウザの中だけです。直近10冒険、合計1000戦・10万詠唱詳細、ログ約256 MiB（JSON文字数×2の保守的な目安）を上限とし、古い冒険・戦闘・詠唱詳細から整理します。戦闘集計は保持している詳細より広い期間を含む場合があり、保持範囲と省略件数を画面で区別して表示します。
- JSON書き出しは現在保持している履歴の保存用です。すでに省略された詳細は含まれません。ログは盤面再生や操作の取り消しには使いません。
- 更新前の保存は、次に確定した詠唱から部分記録として開始します。昔の詠唱詳細を集計から推定しません。旧来の直近5戦の貢献レポートは独立して保持します。
- 履歴と本体はIndexedDBの同じトランザクションで保存します。毎手は変更した戦闘だけを書き込み、localStorageには小さな本編予備保存を残します。旧保存は最初の保存成功まで変更しません。容量不足・DB拒否時は元DBを消さず、本編と直近履歴をlocalStorageへ予備保存して警告します。保存自体が拒否された場合も以前の正常な保存は削除しません。別タブが先に更新した場合は上書きを止め、再読込を案内します。履歴だけが破損している場合は盤面・敵HP・抽選済み報酬を維持し、履歴を再開します。

大容量保存の保持数は目標上限であり、ブラウザや空き容量による保証はありません。サイトデータ削除・端末交換で失われるため、大切な記録はJSON保存を推奨します。検証範囲は [`HISTORY_RETENTION_VERIFICATION.md`](HISTORY_RETENTION_VERIFICATION.md) を参照してください。
